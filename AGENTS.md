# lifefs

Rust (Tauri 2) app for Mac, and later Windows. Its first module, Owed, reads Slack, Gmail, WhatsApp
and meeting notes, and keeps one list of to-dos and follow-ups as notes in an Obsidian vault. Read
`docs/` first. `docs/04-checklist.md` says what is done and what is next.

## Where things live

| Path | Contents |
| --- | --- |
| `docs/` | Overview, architecture, roadmap, checklist. The current plan. |
| `crates/app/` | The `lifefs` binary: the Tauri window and the `sweep` subcommand. UI in `ui/`. |
| `crates/<name>/` | One library crate per job. Each `lib.rs` doc comment states the job. |
| `fixtures/synthetic/` | Made-up message windows. The only place `.jsonl` is allowed. |
| `fixtures/private/` | Real messages and the labelled set. Gitignored. |
| `scratch/` | Working scripts and dumps, one `YYYY-MM-DD-what/` per job. Gitignored. |

`AGENTS.local.md` (gitignored) holds pointers to private research. Read it when it exists.

## Conventions

- Use an existing library first. Build our own code only when no library fits, and record why in
  `docs/02-architecture.md`.
- Mac is the primary dev machine. Every crate except the app's OS-specific parts must also build on
  Windows. The Check workflow runs clippy there.
- No tests in the first phases. We test live. `just check` is the gate and runs on each push.
- No Keychain yet. Secrets go in `secrets.toml` in the app data folder, mode 0600, outside the
  vault.
- Stored times are UTC. Times shown to me are IST.
- Read-only on every source. A message cannot trigger an action: models get no tools and return
  JSON that code validates.
- Raw messages never enter the vault or this repo. The pre-commit privacy hook enforces the repo
  side.
- The repo is public. No secrets, client data, client names or private paths in commits. Docs never
  link private notes.
- Nothing committed refers to `scratch/`.
- Stay on Tauri 2 stable. Tauri 3 is alpha.
- `crates/app/ui/src/bindings.ts` is generated by debug builds. Never edit it by hand. Commit it
  after a command changes.
- Logs go through `tracing` as JSON on stderr, with OpenTelemetry field names.
